# React 前端完整重构规格（本地草稿，尚未发布 Issue）

## Problem Statement

当前管理端基于 Vue 3 与 Element Plus。希望将整个前端迁移至 React + TypeScript + Vite 与官方 shadcn/ui，形成统一的新界面，同时保留现有业务行为与后端 API 契约；不能让尚未完成的页面影响生产面板。

## Solution

开发期在独立应用中逐模块重建全部管理端功能，通过开发代理连接原 API，保留现有 Vue 面板作为正式入口。采用统一设计令牌与后台布局，保留信息架构、功能入口及可迁移的扩展能力。建立逐模块功能对照清单和回归证据；全部覆盖且验证通过后才将构建入口整体切换至 React，并保留重新构建、部署旧 Vue 前端的能力直至稳定验收。

## User Stories

1. 作为面板用户，我希望使用新界面访问原有全部功能入口，以便不因重构失去功能。
2. 作为管理员，我希望登录、退出与会话过期的行为保持一致，以便安全管理面板。
3. 作为管理员，我希望路由、菜单及操作权限按原规则生效，以便用户仅看到和执行被允许的操作。
4. 作为企业版用户，我希望许可证与受保护功能的跳转保持一致，以便正确访问授权能力。
5. 作为多节点用户，我希望切换当前节点后所有请求和显示内容对应目标节点，以便避免跨节点误操作。
6. 作为用户，我希望语言切换、缺失文案回退及持久化偏好保持可用，以便继续使用熟悉的语言。
7. 作为用户，我希望明暗主题和有意义的偏好在切换后尽量延续，以便无需重复配置。
8. 作为用户，我希望侧栏、顶部区域、标签与工作区在桌面及移动端保持可用，以便高效导航。
9. 作为用户，我希望首页与概览提供原有数据及交互，以便快速了解面板状态。
10. 作为用户，我希望应用商店与已安装应用、网站、数据库、容器和文件管理的原有操作继续可用，以便维护服务。
11. 作为用户，我希望监控、日志、计划任务、备份和安全相关功能继续可用，以便运维和排错。
12. 作为用户，我希望终端、任务列表及长时操作反馈保持可靠，以便了解执行结果。
13. 作为管理员，我希望节点、用户、设置及系统维护功能继续可用，以便管理面板。
14. 作为用户，我希望表单校验、确认弹窗、提示与错误处理不因视觉重构而改变业务结果，以便安全完成操作。
15. 作为扩展开发者，我希望有新的 React 扩展入口与迁移指引，以便迁移扩展功能；旧 Vue 扩展组件不要求原样运行。
16. 作为开发者，我希望新旧前端在开发期互不覆盖，以便验证新界面时不影响正式入口。
17. 作为发布负责人，我希望以功能对照、自动化及浏览器回归证据作为切换门禁，以便控制发布风险。
18. 作为发布负责人，我希望发布后仍能重新构建和部署旧前端，以便在异常时回退。

## Implementation Decisions

- 新应用采用 React、TypeScript、Vite 与官方 shadcn/ui；与原 Vue 工程独立建设，开发时通过代理访问原 API。保留现有后端业务逻辑和接口契约。
- 视觉采用 shadcn/ui 风格的统一设计系统，重做视觉层级，保留 1Panel 的信息架构、导航语义和用户可观察行为。
- 原有 Vue Router、Pinia、Vue I18n、Element Plus 使用方式迁移为 React 生态适配；API 请求的语言、节点、入口码、凭据、CSRF、业务错误处理语义必须保持一致。
- 先建立可运行的骨架、权限和 API 适配、国际化、设计令牌、模块对照与测试约定，然后按领域迁移。每个阶段标记已覆盖与未覆盖功能。
- 保留有明确业务含义的浏览器偏好和认证行为；不能安全复用的临时状态重新初始化。不承诺兼容 Pinia 内部序列化格式。
- 开发期不让未完成应用接管正式路由；最终验收通过后才修改静态资源嵌入、SPA 回退与发布构建。资源路径和安全入口应避免与旧前端冲突。
- Vue 扩展组件无需无修改运行，但新的扩展能力必须提供迁移方式。切换后不立即删除旧前端的源码、依赖和构建能力。
- 不在此项目中变更后端 API、数据库或产品业务规则。

## Testing Decisions

- 主要测试接缝是浏览器到新前端再到现有后端的用户可观察行为；不以组件内部实现作为验收目标。
- 对照旧前端逐模块建立入口、操作、权限、异常态、响应式和语言/主题清单。关键流程做浏览器回归，覆盖登录、权限、节点切换、数据操作和会话失效。
- 对 API 适配边界测试请求头、CSRF、凭据与错误码处理；自动化覆盖关键行为，并执行类型检查、lint、构建。
- 现有前端主要使用 Node 内置测试与 TypeScript/Vite 构建验证，浏览器端回归与新应用测试基线需要新建；完成首个节点不等于完成全量迁移。
- 最终切换前验证发布构建、core 静态嵌入、SPA 回退、认证入口、旧版本回退路径及全模块对照清单。

## Out of Scope

- 后端业务逻辑、数据库和 API 契约重设计。
- 开发期把半成品新前端作为正式面板入口。
- 无修改运行既有 Vue 扩展页面。
- 首个交付节点就宣称所有模块已迁移，或在切换当天删除旧 Vue 工程。
